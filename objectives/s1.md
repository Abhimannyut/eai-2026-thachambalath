## By the end of this session, you can

1. **Explain** what enterprise application integration is. Give the difference between application integration, data integration and process integration.
2. **Identify** the four integration architectures: point-to-point, hub-and-spoke, enterprise service bus and event-driven.
3. **Analyse** the coupling between two systems. Name the type of coupling. Name what the coupling costs.
4. **Recognise** the point-to-point growth problem. Calculate the number of connections for N systems.
5. **Apply** the four integration styles: file transfer, shared database, remote procedure invocation and messaging.
6. **Select** an integration style for a given requirement. Give a reason for your selection.
7. **Evaluate** when to buy integration software and when to write it.
8. **Explain** why the business process sets the integration boundary.

## The hard parts

These are the parts that people find difficult. Read them before the
session. If you cannot follow one of them, make it your question.

- **Coupling is not the number of connections.** It is the number of reasons that two systems must change together. Two systems with one connection can be tightly coupled. Two systems with many messages can be almost independent.
- **Architecture and style are two different decisions.** The architecture is the shape of the landscape. The style is how the data moves along one connection. You make both decisions, and you make them separately.
- **No architecture is best.** Each one is a trade. Your mark comes from the reason you give, and not from the option you select.

## Self-check

Answer these before the session. They are not graded, and I do not
collect them. They show you which of the hard parts you cannot yet
explain. **A question that you cannot answer is your question for the
session.**

1. A company has 10 systems with point-to-point connections. A new rule says that the company must log all customer-data transfers. How many integrations must change?
   <details><summary>Answer</summary>

   Possibly all of them, which is up to 45 connections. There is no central point. You must change and release each connection separately.

   </details>

2. Three services use one PostgreSQL database. Why is it difficult to release one service alone?
   <details><summary>Answer</summary>

   A schema change by one service can stop the other two. All three services need one coordinated release. They are not independent.

   </details>

3. A company sends its product catalogue to 50 retail stores each night. Which integration style is correct?
   <details><summary>Answer</summary>

   File transfer. The data is bulk data, the frequency is low, and the stores have small integration capability.

   </details>

## What the assignment will require

**PA1 — legacy file ingestion**

PA1 gives you the file transfer style from slide 25. You read a fixed-width order export and a customer file.
The assignment assumes that you can do these things:
- Read a file as bytes, and not as text.
- Select a character encoding, and not accept the default.
- Take a field from a fixed position in a line.
- Keep a decimal amount as a string.
- Report a bad record. Do not stop the program, and do not remove the record.
